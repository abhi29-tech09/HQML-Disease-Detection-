## What this module contains

| `feature_order.json` | Generated by `pipeline_demo.py` — the locked, exact column order. Anything calling this model at inference time (the AIKYA chat extraction, the pain-map body-region data) MUST align to this file or the amplitudes mean the wrong thing. |

## Architecture (see diagram above)

```
symptom vector (34 features)
        │
Classical front-end: normalize to unit length, zero-pad 34 → 64 (2^6)
        │
Quantum encoding: AmplitudeEmbedding onto 6 qubits (no trainable parameters)
        │
Variational ansatz: StronglyEntanglingLayers, trainable weights (Deliverable #3 trains these)
        │
Measurement: <Z> expectation value per qubit → 6 real numbers
        │
Classical readout head: small classical layer → 50-class disease probabilities
```

## Why amplitude encoding, not angle encoding

With 34 raw symptom features, angle encoding (one qubit per feature, one rotation gate per feature) would need 34 qubits. Amplitude encoding instead loads the entire feature vector into the *amplitudes* of a single quantum state, needing only `ceil(log2(n_features))` qubits — **6 qubits for 34 features** (padded to 64 = 2⁶). This is the standard reason amplitude encoding is preferred for feature-heavy NISQ-era classifiers: it trades circuit depth (amplitude embedding circuits are deeper than simple rotation gates) for a dramatic reduction in qubit count, which matters more on today's noisy, qubit-limited hardware.

## Backend-agnostic design

`quantum_encoding.get_device(n_qubits, backend=...)` is the single switch point:
- `backend="simulator"` (default, what everything above runs on): PennyLane's `default.qubit`, free, fast, unlimited local use.
- `backend="ibmq"`: stubbed with a clear `NotImplementedError` explaining exactly what's needed to enable it (the `pennylane-qiskit` plugin + IBM Quantum credentials) — not faked, not silently falling back to the simulator.

Every other module only ever talks to a PennyLane `device`/`QNode` object, never to `default.qubit` directly, so swapping to real hardware later is a one-line change here, not a rewrite.

## Known limitations

- The classical readout head in `hybrid_circuit.py` is a random-weight stub for shape-verification only. Deliverable #3 replaces it with a properly trained layer as part of the end-to-end training loop.
- `StronglyEntanglingLayers` with `n_layers=2` (36 parameters) is a reasonable starting depth for 6 qubits on a simulator; Deliverable #3's training results will determine whether more or fewer layers are actually needed — deeper isn't automatically better, especially if this ever targets real NISQ hardware where circuit depth directly costs accuracy to noise.
- The `all-zero symptom vector` case is explicitly rejected (`ValueError`) rather than silently producing a meaningless uniform-superposition prediction — the calling chat UI should require at least one symptom before invoking the model.
